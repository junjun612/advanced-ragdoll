# 랙돌 설정 (`config/characters/xbot.json`) — 좌표계, 규약, 결정

생성: `npm run ragdoll:gen` (= `tsx tools/genRagdoll.ts "assets/fbx/X Bot.fbx"`).
입력은 X Bot FBX와 `config/genRagdoll.json`(바디 목록, 질량비, 관절 제한, 형상 방식, A포즈 각)이다. 손으로 고친 값은 `config/characters/xbot.overrides.json`에만 둔다. 타입 정의는 `src/sim/character/characterDef.ts`에 있다.
`tests/ragdollConfig.test.ts`가 커밋된 `xbot.json`이 생성기 결과와 같은지 확인한다. 설정이나 생성기를 고쳤으면 다시 생성해서 커밋한다.

## 1. 좌표계

| 좌표계 | 정의 |
|---|---|
| 월드 | SPEC 4장: Y 위, +Z 정면, +X 캐릭터 왼쪽, 미터 |
| 바디 로컬 | 원점 = `restPosition` = 형상 중심. 회전 = `restRotation`. 팔 사슬(Arm/ForeArm/Hand)을 뺀 바디는 rest 회전이 항등이라 로컬 축이 월드 축과 같다. 팔 사슬은 A포즈 회전(아래 2장)만큼 돌아 있다. |
| 형상 | 바디 원점에 놓는다(오프셋 없음). 캡슐 축은 형상 로컬 +Y이고 `shape.rotation`(바디 로컬 기준)으로 돌린다. 박스는 바디 축 정렬이다. |
| 관절 | 아래 3장. `frameInParent`·`frameInChild`는 관절 좌표계의 바디 로컬 회전이다. |

사원수는 `[x, y, z, w]`이고 합성은 `multiplyQ(a, b)` = b 다음 a 순서다(`src/sim/math/quat.ts`).

## 2. rest 자세: 팔 내린 A포즈

- X Bot 바인드는 정확한 T-포즈다(스파이크 2장). 팔 사슬 전체를 어깨 관절(`{S}Arm` 본 위치) 중심으로 **수평 아래 60°** 돌린다. 회전축은 `바인드 상완 방향 × (0,−1,0)`(왼팔 −Z, 오른팔 +Z)이다. 각도는 `config/genRagdoll.json`의 `restPose.armDownDeg`에 있고, 결과 JSON의 `restPose.armDownDeg`에도 기록한다.
- 몸통·다리·머리는 바인드 그대로다. 팔꿈치는 펴진 상태(굽힘 0, 제한 경계)다.
- 60°로 정한 이유: 전완·손이 Hips·허벅지와 충분히 떨어져 있다(rest에서 손목 x ≈ 0.43m, 겹침 없음). 스윙 콘(100°) 안에 들어간다. 더 내린 자연스러운 서기 자세는 `config/poses/stand`의 몫이다.

## 3. 관절 좌표계 규약

모든 관절 좌표계는 다음과 같다(rest 월드 기준 값은 `joint.axesWorld`).

- **Y = twist 축**: 자식 분절 방향(관절 → 자식 끝). 발목만 예외로 정강이 방향(부모 분절, 아래쪽)이다. SPEC 6.3의 발목 "비틀기 ±5"는 정강이 축 회전이고, "옆 굽힘 ±20"은 발 안쪽·바깥쪽 젖힘(inversion/eversion)으로 읽었다.
- **X = flex 축**: `정규화(자식 분절 방향 × flexToward)`를 Y에 수직이 되도록 맞춘 것이다. 오른손 법칙으로 +각도만큼 돌리면 자식 분절이 `flexToward` 쪽으로 움직인다. 즉 **SPEC 6.3 굽힘의 + 방향**이다.
- **Z = side 축** = X × Y (오른손 좌표계).
- rest에서 부모 쪽 관절 좌표계와 자식 쪽 관절 좌표계의 월드 회전이 같다. 그래서 **rest의 관절 상대 회전은 항등**이고, 각 제한은 rest 기준 각이다.

| 관절 | 종류 | flexToward(바인드) | rest flex 축(월드) | +flex의 뜻 | 제한(도) |
|---|---|---|---|---|---|
| Spine, Spine2 | 구형 | +Z 앞 | +X (캐릭터 왼쪽) | 앞으로 숙임 | flex −20~35, side ±25, twist ±25 |
| Head (목) | 구형 | +Z | +X | 고개 숙임 | flex −40~50, side ±35, twist ±60 |
| 어깨 Arm | 구형 | +Z | 왼 (−0.87, −0.5, 0) / 오 (−0.87, 0.5, 0) | 팔 앞으로 | 스윙 콘 100, twist ±70 |
| 팔꿈치 ForeArm | 경첩 | +Z | 어깨와 같음 | 전완이 앞으로 접힘 | flex 0~145 |
| 손목 Hand | 구형 | (0,−1,0) 바인드 손바닥 쪽 | 왼 −Z / 오 +Z | 손바닥 쪽으로 굽힘 | flex ±60, side ±30, twist ±10 |
| 고관절 UpLeg | 구형 | +Z | −X | 허벅지 앞으로 듦 | flex −20~110, side ±40, twist ±35 |
| 무릎 Leg | 경첩 | −Z 뒤 | +X | 정강이 뒤로 접힘 | flex 0~140 |
| 발목 Foot | 구형 | +Y 위 | −X | 발끝 듦(배측굴곡) | flex −40~25, side ±20, twist ±5 |

- 경첩의 `axis`는 flex 축을 부모 바디 로컬로 쓴 것이다(SPEC 6.4 예시 필드).
- X Bot 바인드에서 손바닥은 아래(−Y)를 향한다(엄지가 +Z 쪽에 있음). 손목 flexToward는 이 값을 쓴다.
- **어깨 스윙 콘 축** (`coneAxisInParent`, Spine2 로컬) = **바인드(T-포즈) 상완 방향 = 왼 +X / 오 −X**. 스파이크가 이 축으로 쟀다: 애니 최대 스윙 78°, HoldWound 목표 최대 84°, 둘 다 100° 안. A포즈 rest(60° 아래)는 콘 축에서 60° 떨어진 콘 안쪽이다. 콘 축을 A포즈 방향으로 두면 팔을 머리 위로 올리는 동작(A포즈에서 150°)이 막혀서 택하지 않았다.
- 구형 관절의 축별 제한을 실제로 어떻게 거는지(generic 관절 / 멀티바디 / 되미는 토크)는 Rapier 스파이크(`docs/SPIKE-rapier.md`) 결론을 따른다. 이 파일은 축과 각만 정한다.

## 4. 바디 형상과 질량

| 바디 | 형상 | 방법 | 값(m) |
|---|---|---|---|
| Hips | 가로 캡슐(축 X) | 아래 결정 1 | r 0.130, 반폭 0.140 |
| Spine | 가로 캡슐(축 X) | 결정 1 | r 0.126 (반폭이 r과 같아 사실상 구) |
| Spine2 | 가로 캡슐(축 X) | 결정 1 | r 0.105, 반폭 0.188 |
| Head | 구 | 중심 = Head·HeadTop_End 중점, 반지름 = Head 본보다 위에 있는 머리 정점까지 거리의 중앙값 | r 0.113 |
| 팔·다리 | 캡슐(분절 축) | 반지름 = 바디 정점에서 분절 선분까지 거리의 중앙값. 길이는 관절~관절(양 끝 반구는 관절 너머로 나감) | 상완 0.048, 전완 0.040, 허벅지 0.072, 정강이 0.055 |
| 손 | 캡슐(Hand→HandMiddle4) | 같은 방법. 캡슐 끝이 중지 끝을 넘지 않게 r만큼 줄인다 | r 0.028 |
| 발 | 박스(월드 축 정렬) | 발 바디 정점의 AABB | 길이 0.250, 폭 0.112, 높이 0.124, 발바닥 y = 0.000 |

- 정점 배정: 정점마다 바디 소속 본(`sourceBones`, SPEC 11.2) 가중치를 바디별로 더해 가장 큰 바디에 넣는다. 그 합이 0.5 이하이면 버린다. 두 스킨 메시(`Beta_Surface`, `Beta_Joints`)를 모두 쓴다.
- 질량비는 SPEC 6.1 표 그대로이고 합은 1.000이다(75kg). 관성은 형상에서 계산하며 `inertiaScale` = 1.0이다.
- 마찰: 발 1.0, 손 0.9, 나머지 0.6 (SPEC 6.2).

## 5. 관절 위치

- 관절은 **자식 바디가 시작하는 본**의 rest(A포즈) 월드 위치에 있다(`jointBone`): Spine→`Spine`, Spine2→`Spine2`, Head→`Neck`, 나머지는 바디 이름과 같은 본.
- `anchorInParent`, `anchorInChild`는 그 점을 각 바디 로컬로 쓴 것이다. 테스트에서 두 값의 월드 위치가 0.1mm 안에서 같고, X Bot 본 위치(팔은 A포즈 적용)와 1cm 안임을 확인한다(실제 오차는 반올림 수준).
- `representativeBone`은 SPEC 11.2 포즈 추출용 대표 본이다(예: Spine 바디의 대표는 `Spine1`). 관절 위치 본과 다를 수 있다.

## 6. 수동 보정 병합

`xbot.overrides.json` 형식은 `{ "bodies": { "<바디 이름>": { 부분 BodyDef } }, ...최상위 부분 필드 }`이다. 객체는 재귀 병합하고, 배열·숫자는 통째로 바꾼다. `$`로 시작하는 키(`$comment`)는 무시한다. 없는 바디 이름은 오류다. 병합은 생성 시점에 하고, 결과 JSON의 `generator.overrides`에 경로를 남긴다. 지금은 비어 있다.

## 7. 결정 (README 결정 기록으로 옮길 것)

1. **몸통 3개를 가로 캡슐로 하고 Hips 반폭을 0.14m로 제한** (2026-10-26)
   - 이유: 스파이크 6번에서 Hips를 세로축 반지름 0.155로 두면, 애니 중 팔-몸통 최소 거리 0.21m에 전완 반지름 0.04를 더했을 때 여유가 1.7cm뿐이었다. 똑바로 내린 팔과도 겹친다. 몸통 단면이 납작해서(반폭 0.15~0.19, 반깊이 0.12~0.14) 세로축까지 거리의 중앙값은 반지름으로 맞지 않는다.
   - 방법: 가로(X축) 캡슐로 둔다. 반지름은 바디 정점 z 범위(2~98 백분위)의 절반, 중심 z는 그 범위의 가운데다. 반폭은 정점 |x|의 98 백분위이고 Hips·Spine은 0.14로 자른다. 중심 높이는 본 위치로 정한다. Hips = Hips 본, Spine = Spine1 본, Spine2 = Spine2·Neck 중점이다. 스파이크 지적대로 스킨 분할이 본과 어긋나서 높이는 스킨으로 정하지 않았다.
   - 결과: Hips 반폭 0.14 + 전완 0.04 = 0.18 → 애니 최소 거리 0.21m 대비 여유 **3cm**. 바로 붙지 않은 몸통 바디 사이 겹침은 없다(Hips 위 1.173 < Spine2 아래 1.314). Spine 아래쪽과 허벅지 위 반구 사이 거리는 8cm다.
   - 대안: 박스(모서리 때문에 구르기·미끄러짐이 튐), 세로 캡슐 반지름 축소(앞뒤 두께가 모자라 엎어질 때 몸통이 바닥에 너무 깊이 들어감).
2. **rest A포즈 = 팔을 수평 아래 60°** (2026-10-26). 이유는 2장. 대안: 45°(일반적인 A포즈, 관절 0점이 실제 서 있는 자세에서 더 멂), 75~80°(서 있는 자세에 가깝지만 전완과 Hips 여유가 2~3cm로 줄어 rest에서 접촉하기 쉬움).
3. **어깨 스윙 콘 축 = 바인드 T-포즈 상완 방향(±X, Spine2 로컬)** (2026-10-26). 이유는 3장. 스파이크 제안을 따랐다.
4. **관절 좌표계 규약 X = flex, Y = twist, Z = side, +flex = SPEC 6.3 굽힘 + 방향**. 발목 twist 축은 정강이로 둔다(3장).
5. **바디 원점 = 형상 중심**: Rapier 바디의 질량 중심이 원점에 오게 해서 토크·관성 계산을 단순하게 한다. 관절 위치는 anchor로 따로 준다.
6. **반지름 정점은 두 메시를 합쳐서 쓴다**: X Bot은 허리·목·관절 띠가 `Beta_Joints`에만 있다. 팔다리 반지름은 Surface만 쓸 때와 1cm 안으로 차이 난다.

## 8. 사람이 확인할 것

- A포즈 각 60°와 어깨 콘 축(T-포즈 방향)이 받아들일 만한지.
- 손 캡슐 반지름 0.028은 손바닥 폭(약 0.09)보다 가늘다. 난간 잡기(v0.8b)에서 문제가 되면 overrides로 키우거나 박스로 바꾼다.
- 발 박스 높이 0.124는 발목 관절 띠(`Beta_Joints`)까지 들어간 값이다. Surface만 쓰면 0.105다. 발목 관절이 박스 안(y 0.087)에 있다.
