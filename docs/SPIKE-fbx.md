# v0.0 스파이크 — FBX 읽기와 쇄골 판단 (SPEC 12장 v0.0 항목 6·7)

실험 코드는 `spike/fbx/`, 수치 원본은 `spike/fbx/out/`에 있다. 모든 좌표는 SPEC 4장 규약(Y 위, +Z 정면, +X 왼쪽, 미터)이다. three 0.186.1 기준.

| 스크립트 | 산출물 |

| `spike/fbx/load.ts` | 공용 로더 (`loadFbx`, `boneMap`) |

실행: `npx tsx spike/fbx/<script>.ts` (프로젝트 루트에서). `npx tsc --noEmit` 결과 `spike/fbx`에서 오류 0건.

## 1. FBX 읽기 경로 (항목 6)

**결론: Node + tsx에서 `FBXLoader.parse(ArrayBuffer, '')`로 읽힌다. DOM 셈(shim)은 하나도 필요 없다.** Playwright 대체 경로는 쓰지 않았다.

```ts
import { FBXLoader } from 'three/examples/jsm/loaders/FBXLoader.js';
const buf = readFileSync(path);
const group = new FBXLoader().parse(buf.buffer.slice(buf.byteOffset, buf.byteOffset + buf.byteLength), '');
```

- 셈이 필요 없는 이유: 이 네 파일에는 텍스처가 없어서 `TextureLoader`(→ `ImageLoader`/`document`)와 `URL.createObjectURL`/`Blob` 경로를 타지 않는다. `window.innerWidth`는 카메라 노드를 만들 때만 쓰는데 카메라가 없다. `load()`(XHR/fetch)를 쓰지 않고 `parse()`를 쓴다. 나중에 텍스처가 들어간 FBX를 읽게 되면 그때 셈이 필요해진다.
- 경고·예외 없음. 네 파일 모두 읽혔다 (X Bot 1.75MB, 애니 1.9~2.7MB, 파일당 수 초).

**주의할 점 (`tools/extractFbxPoses.ts`가 처리해야 함)**

1. **본 이름에서 `:`가 빠진다.** `PropertyBinding.sanitizeNodeName`이 예약 문자를 지워 `mixamorig:Hips` → `mixamorigHips`가 된다. 트랙 이름도 `mixamorigHips.quaternion`이다. 접두어 `mixamorig`를 떼면 SPEC 바디 이름이 된다.
2. **본이 중복된다.** 메시가 두 개(`Beta_Surface` 65본, `Beta_Joints` 64본)이고, 두 스킨이 공유하는 본마다 FBXLoader가 **같은 이름의 자식 본(로컬 항등)** 을 하나 더 만든다. traverse하면 Bone 129개가 나오고 고유 이름은 65개다. 이름으로 찾을 때는 **처음 나오는(바깥) 본**을 써야 한다. 로컬이 항등이라 월드 변환은 같다.
3. **단위**: `GlobalSettings.UnitScaleFactor = 1`(cm). 루트 그룹 scale은 1이므로 ×0.01은 직접 해야 한다.
4. **클립**: 파일마다 `mixamo.com`(실제 애니)과 빈 `Take 001`(0초, 트랙 0개)이 있다. `mixamo.com`을 이름으로 고른다.
5. **트랙 구성**: 53개 = Hips.position 1개 + quaternion 52개. 끝 본 13개(`HeadTop_End`, 손가락 `*4` 10개, `*Toe_End` 2개)에는 트랙이 없다. scale 트랙은 없다.
6. 바인드: 두 메시 모두 `bindMatrix`가 항등이다. `boneInverses`는 클러스터 TransformLink에서 온다.

## 4. 쇄골 판단 (항목 7)

### 4.1 모델

- 어깨 S = LeftArm 위치에 Spine2와 강체로 고정(쇄골 바디 없음). 왼손 기준이고 좌우 대칭이다.
- 2링크: L1 = 0.278, L2 = 전완 0.283 + 손바닥 중심 오프셋 0.052(손목→중지 MCP의 55%, 손은 전완과 일직선) = 0.336. 도달 범위 r ∈ [**0.193**(팔꿈치 145°), **0.614**].
- 스윙 콘 100°(반각). 콘 축은 두 가지로 쟀다. `lateral`은 T-포즈 rest 방향(±X)이고 SPEC을 문자 그대로 읽은 것이다. `tilted`는 앞 45°·아래 30°로 기울인 축이다. 팔꿈치 0~145°이고 스위블은 2° 간격으로 전부 탐색했다. 비틀기 ±70°와 손목 제한은 무시했다.
- 몸통 관통 검사: X Bot 몸통 정점(|x| < 0.152)으로 2cm 높이 슬라이스마다 타원 단면을 만들었다. strict는 상완 여유 0.04, 전완 0.035이고 손 쪽 15%를 면제한다. relaxed는 상완 0.03, 전완 0.02이고 손 쪽 40%를 면제한다. relaxed는 손목을 굽혀 손바닥을 대고 전완이 가슴에 얹히는 접촉을 허용한다.
- 상처 목표: 표면 정점 + 3cm(바깥 방향). 가슴 y = 1.29(어깨 −0.15), 배 y = 1.10(Hips +0.07), x는 ±0.07~0.09.
- 쇄골 모델: SC = LeftShoulder 본 머리, 쇄골 길이 0.108. 올림·내밈을 각각 ±20°(5° 간격)로 돌리고 콘 축도 함께 돈다. 어깨 최대 이동은 2·0.108·sin10° = **0.038m**다.

- 실패는 대부분 **몸통 관통 검사**에서 나온다. 반대쪽 목표는 전완이 가슴이나 배에 얹혀야 하는데, 몸통 단면 모델이 거칠어서(AABB에 내접한 타원) 경계 판정이 많다. 반대쪽 배는 어깨를 1cm만 옮겨도 통과하므로 모델 오차 수준이다.
- 허벅지는 거리 문제다. 중간 허벅지까지 0.675m인데 팔 도달은 0.614m이고, 쇄골(최대 3.8cm)로도 모자란다. 거리만 보면 상체를 **37.5°** 숙여야 하고(콘+relaxed로는 57.5°), 쇄골을 써도 37.5°다. 다리 상처는 HoldWound에 웅크림(척추·고관절 굽힘)이 반드시 함께 가야 한다.

### 4.3 (b) 허리 높이 난간 (`reach.json` rails)

난간 위 잡는 위치는 자유롭게 골랐다(옆 난간은 z, 앞 난간은 x를 −0.4~0.6 범위에서 탐색). 거리는 몸 중심선(x = 0 또는 z = 0)부터 쟀다. 손 쪽 난간 기준이다. 숙임은 Hips 중심으로 상체를 기울인 것이다. 콘 축 두 가지의 결과가 같았다. 난간 도달을 제한하는 것은 콘이 아니라 팔 길이다.

| 난간 | 높이 | 자세 | 최대 거리, 쇄골 없음 | 쇄골 ±20° | 증가 |
|---|---|---|---|---|---|
| 옆 | 1.04 (Hips) | 똑바로 | **0.61** | 0.64 | +0.03 |
| 옆 | 1.04 | 20° 숙임 | 0.80 | 0.80 | 0 |
| 앞 | 1.04 | 똑바로 | **0.37** | 0.45 | +0.08 |
| 앞 | 1.04 | 20° 숙임 | 0.52 | 0.60 | +0.08 |
| 옆 | 0.90 | 똑바로 | 0.44 | 0.49 | +0.05 |
| 옆 | 0.90 | 20° 숙임 | 0.67 | 0.69 | +0.02 |
| 앞 | 0.90 | 똑바로 | **0.20 미만** | 0.30 | — |
| 앞 | 0.90 | 20° 숙임 | 0.32 | 0.44 | +0.12 |

요청 범위 0.3~0.6m와 비교하면 다음과 같다.
- 옆 난간(1.04m)은 똑바로 서서 0.6m까지 닿는다. 범위 전부 충족.
- 앞 난간(1.04m)은 똑바로 서서 0.37m까지(배 앞면에서 약 0.24m) 닿는다. 20° 숙이면 0.52m다. 0.6m는 숙임 + 쇄골이 있어야 겨우 닿는다.
- 앞 난간(0.90m)은 똑바로 서서는 거의 닿지 않는다. 숙여야 한다.
- 20° 숙임의 효과(+0.15~0.23m)가 쇄골의 효과(+0.02~0.12m)보다 2~7배 크다.

### 4.4 권고: **16바디 유지** (쇄골 바디 추가 안 함)

근거:
1. HoldWound의 핵심 목표인 반대쪽 가슴·배와 같은 쪽 가슴·배 4곳은 고정 어깨에서 운동학적으로 모두 닿는다(팔꿈치 89~130°, 스윙 ≤70°). 반대쪽 가슴은 접촉 허용(relaxed) 판정으로도 통과한다. 반대쪽 배는 어깨를 1cm 옮기면 통과하는 경계 사례다.
2. 쇄골 ±20°가 주는 어깨 이동은 최대 3.8cm다. 난간 도달 증가는 옆 +3cm, 앞 +8cm로, 상체 20° 숙임(+15~23cm)이나 한 걸음보다 훨씬 작다.
3. 고정 어깨로 실패하는 목표(허벅지 중간, 반대쪽 옆구리)는 쇄골로도 풀리지 않는다. 이것은 척추·고관절 굽힘과 몸통 비틀기의 문제다.
4. 쇄골 바디를 넣으면 질량 1kg 안팎의 작은 바디 2개가 Spine2(12kg) 옆에 붙어 질량비가 커진다. 근육 안정성(항목 3) 측면에서 불리하다.

보완책(16바디 안에서 처리):
- 반대쪽 배와 어깨처럼 경계에 있는 목표는 HoldWound IK에서 Spine2 비틀기(±25°)를 상처 쪽으로 일부 쓰거나, 손바닥 목표 띄움(3cm)을 접촉 허용 쪽으로 다룬다.

## 5. SPEC 가정과 다른 점 (사람 확인 필요)

1. **11.2 "본 66개"** → X Bot과 세 애니 모두 고유 본 **65개**다(트랙이 있는 본 52개 + 끝 본 13개).
2. **6.3 어깨 "스윙 콘 100"** → 콘 축이 정의돼 있지 않다. rest가 정확한 T-포즈이므로 축을 rest(±X)로 두면 100° 반각이 애니(최대 78°)와 HoldWound 목표(최대 84°)를 모두 덮는다. 축을 rest 방향으로 명시하자고 제안한다.
3. **다리 HoldWound**: 똑바로 선 자세로는 같은 쪽 허벅지 중간에 손이 닿지 않는다(0.675 > 0.614m). 대표 장면 세부 규칙의 "가까운 손을 상처로"를 다리에 적용하려면 상체 숙임이 필요하다. 20° 숙임(d = 0.651)으로도 부족하고 최소 37.5°가 필요하다.
4. **루트 모션**: SPEC은 루트 모션을 직접 가정하지 않았다. 확인 결과 걷기 두 클립은 `kept` 상태(+1.39m / −1.16m)이고, Idle은 제자리(±2cm 흔들림)다. `rootMotion: removed`를 만들려면 Hips xz를 첫 프레임 기준으로 빼야 한다. SPEC과 충돌은 없다.
5. 11.2의 "rest 보정"은 이 자산 묶음에서는 항등이다. X Bot과 애니의 rest 로컬 변환이 같고, rest = bind = T-포즈이기 때문이다.
6. 팔-몸통 자기 충돌(6.2): Hips 반지름(0.155)과 전완(0.038)을 그대로 쓰면, Mixamo 애니에서 팔과 Hips 축 사이 최소 거리(0.21m)와의 여유가 1.7cm뿐이다. 똑바로 내린 팔(x = 0.152)은 Hips 반폭(0.170)과 겹친다. v0.1에서 Hips 형상을 캡슐 반지름 대신 납작한 형상으로 하거나 반지름을 줄여야 한다.
